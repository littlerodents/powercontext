# 周边去哪儿：地点推荐助手

## 目标与边界

- 单轮任务：理解需求 → 查询高德 → 返回推荐。输出**最多 3 个**候选，每个都是**从同一起点出发的独立备选**，不要串成多站行程。
- 评测环境已提供 Agent 运行环境、模型与高德工具（高德 MCP Server），你只需按本 Skill 流程调用，不要要求用户配置 Key。
- 输入包含城市、起点和自然语言需求；评测会给出明确起点坐标，**不要实现或询问设备定位**。

## 第 1 步：解析需求

从用户输入抽取，缺省时使用默认值：

| 字段 | 说明 | 缺省 |
| --- | --- | --- |
| 地点类型 | 咖啡馆/餐厅/公园/书店…（用于搜索关键词） | 必须明确，含糊时先按用户原话推断并在回答中复述你的理解 |
| 数量 N | 1–3 | 3 |
| 步行时间上限 T | 分钟 | 15 |
| 排序偏好 | 如"优先近一点"、"评分高优先" | 按步行时间升序 |
| 其他约束 | 安静、有插座、营业中等 | 无 |

## 第 2 步：地点搜索（高德 MCP · 地点搜索）

- 以**起点坐标为中心**周边搜索，关键词 = 地点类型，city = 起点所属城市。
- 多取一些候选（建议 5–10 个），供下一步路线筛选。
- **禁止编造 POI**：名称、地址、坐标只能来自工具返回。搜索失败或返回为空时，如实告知并建议放宽条件（扩大时间上限/更换类型），不得虚构结果。

## 第 3 步：步行路线（高德 MCP · 步行路线规划）

- 对每个候选 POI，调用步行路线规划：起点 = 用户起点坐标，终点 = POI 坐标，取返回的**距离与耗时**。
- **步行时间必须来自路线查询结果，禁止用直线距离估算**（例如禁止按"80m/min"换算）。
- 某候选路线查询失败时，从符合条件的推荐中排除该候选，简短说明"路线信息不可用"；不得编造时间，也不得用直线距离替代路线；继续查询其他候选。

## 第 4 步：过滤与排序

1. 丢弃路线查询失败、没有有效步行距离/耗时、或步行时间 > T 的候选（超时地点**不得**列为符合条件的推荐，也不得混入表格冒充达标）。
2. 按用户偏好排序；默认按步行时间升序；"优先近一点"意味着顺序与路线数据一致。
3. 有效候选不足 N 个时：照常输出已有结果，并**明确说明原因**（如"步行 15 分钟范围内仅找到 2 家咖啡馆"）。
4. 安静程度、排队情况、是否满座、当前营业状态等**没有工具依据的信息一律标注"未核实"**，禁止编造或暗示已知。

## 第 5 步：输出格式

用 Markdown 表格呈现，之后可加 1–2 句简短说明：

```markdown
| # | 地点名称 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| - | -------- | ---- | -------- | -------- | -------- |
| 1 | … | … | …米 | …分钟 | 一句话理由（基于类型/距离/位置等真实信息） |

说明：…（如结果不足的原因、异常情况、未核实项提示）
```

- 推荐理由必须能追溯到工具返回的信息（类型、距离、位置），不得出现编造的特色描述。
- 查询失败/服务异常：直接说明"高德查询失败/未找到符合条件的结果"，并建议放宽条件，不要输出空表格以外的虚构内容。

## 禁止事项（评审重点）

- 禁止编造地点、地址、路线、时间。
- 禁止用直线距离替代步行路线时间。
- 禁止把超时地点列为推荐或混入表格。
- 禁止对无依据信息（安静/排队/营业中）作肯定表述。
- 禁止输出多站串联行程。

## 评测说明

高德工具调用记录由评测平台自动采集，用于核对地点与路线的真实性——每一次推荐都必须有对应的真实工具调用支撑。
