# StepFun 性能与质量实测

2026-11-05，Apple M3 Pro / 18 GB / macOS 26.2，Chrome 用户代理 156，Node.js 22.23.2，seekdb 1.4.0.0，seekdb-js 1.4.0，Transformers.js 3.8.1。数据全部为合成英文文本：12 个文档，每条查询人工指定 1 个相关文档，共 8 条查询；使用 seekdb 混合检索 Top 3。以下是一次热缓存实测，不是统计显著的通用性能结论。完整逐条结果及时间见 `benchmark-result.json`。

| 精度 / WebGPU | ONNX 权重字节 | 相对 FP32 的体积降低 | Recall@3 | 单条逐次向量化 12 条 | 最多 8 条一批 |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32 | 90,387,606 | 基线 | 8/8 | 52.0 ms | 12.6 ms |
| FP16 | 45,297,825 | 49.9% | 8/8 | 56.0 ms | 10.1 ms |
| q8 | 22,972,370 | 74.6% | 1/8 | 290.1 ms | 140.3 ms |

FP16 的单次批量测量约为逐条的 1/5.54；模型加载分别为热缓存 FP32 260.1ms、FP16 126.6ms、q8 323.1ms，不代表首次下载耗时。FP16 数据写入后的单次索引刷新 636ms，8 次混合检索的服务端 p50 7ms。不同测量受缓存、浏览器、GPU 和数据库负载影响。

**降级与一致性。** 在测试页面遮蔽 `navigator.gpu` 后选择自动后端：FP16 实际使用 WASM，预期 refund 文档仍在 Top 3；同一查询的 WebGPU/WASM 向量余弦为 0.999989。FP16 同文档单条/批量输出最小余弦为 0.999984。q8 在此设备上单条/批量最小余弦仅 0.386，WebGPU/WASM 同查询余弦为 -0.039，因此不用于主应用；原因尚未进一步归因到具体运行时组件。

**真实 seekdb 集成。** `server/integration-result.json` 记录 12/12 检查通过：写入/哈希去重、修改检测、刷新、原文和排名、模型空间隔离、缩短文件清除旧尾块、非法维度拒绝。20 次热身后的 HTTP 混合检索样本 p50 8.8ms、p95 10.5ms；测试集合只有两个人造 chunk，此延迟不代表大规模负载。

**复现。** 按 README 启动服务，打开 `/benchmark.html`，点击“运行实测”，完成后下载 JSON；首次运行会下载模型权重，后续可能命中浏览器缓存。应用检索完全通过 seekdb；实测页另用向量点积做独立诊断参照，不参与应用检索结果。
